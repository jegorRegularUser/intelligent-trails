# Карточка места — правила и шаблоны

> Дизайн этого документа первичен по отношению к коду. Слой мест: чистая логика
> `src/lib/places` + презентационные компоненты `src/components/places`.
> Продуктовый контекст: `docs/PRODUCT.md` — карточка существует **внутри прогулки**,
> не сама по себе; принцип **честной деградации** распространяется на каждое поле.

## Зачем карточка

Карточка места отвечает ровно на три вопроса пешехода:

1. **Что это?** — имя, тип (kind), адрес.
2. **Зачем останавливаться?** — слот «почему сюда» (заполняет движок прогулки,
   карточка только отводит под него место).
3. **Работает ли сейчас?** — бейдж open / closed / unknown.

Мы не справочник: карточка не показывает рейтинги, отзывы, фото — только то,
что нужно в момент остановки на маршруте.

## Вход и выход

Сырьё — `ReverseGeocodeResult` из замороженного контракта geo-слоя
(`src/lib/geo/types.ts`) плюс кандидаты вокруг точки:

```
buildPlaceCard(reversed, nearby, nearestRoad?, opts)
opts: { locale: 'ru' | 'en', timeZone?: string, at?: Date }   // at по умолчанию = сейчас
```

Выход — `PlaceCard`: готовые к показу строки для запрошенной локали
(`name`, `kindLabel`, `address`, `distanceLabel`, `nearbyLabel`),
разрешённый kind с иконкой, `openState: 'open' | 'closed' | 'unknown'`.

Локализация данных (kind-подписи, «рядом», расстояния) живёт в lib и выбирается
параметром `locale`. Локализация UI-хрома (тексты бейджа и т.п.) — namespace
`Places.*` в `messages/{ru,en}.json`, читается компонентами через next-intl.
Локаль билдера и локаль страницы обязаны совпадать — это забота вызывающего.

## Приоритеты главного объекта (порт из отработанного Java-решения)

Кандидаты = `reversed` (объект в точке) + `nearby`. Дорога приходит отдельным
аргументом `nearestRoad` (дороги в `nearby` для правила 1 не участвуют).

| # | Правило | Условие |
|---|---|---|
| 1 | **Именованный объект** — здание/POI с именем (не дорога) | ≤ 20 м; из подошедших — ближайший |
| 2 | **Дорога** (улица) | принимается **только** если ≤ 5 м |
| 3 | **Дом с адресом** (`address` или `addr:housenumber`) | ≤ 20 м; ближайший |
| 4 | **Fallback** | ближайший дом (kind `house`); если дома нет — ближайший любой кандидат; если и кандидатов нет — честная карточка «не знаем» |

Нюансы:

- **Именованный объект бьёт дорогу, даже если дорога ближе.** Улица в 3 м
  против кафе с именем в 18 м → показываем кафе: «ты на такой-то улице» не даёт
  пешеходу ничего, имя даёт.
- **Дорога выигрывает только вплотную (≤ 5 м)** — когда человек буквально стоит
  на ней и имени рядом нет.
- Расстояние берётся из `distanceMeters`. Для `reversed` отсутствие дистанции =
  объект в точке (0 м). Для кандидата из `nearby` отсутствие дистанции = исключён
  из дистанционных правил (не догадываемся).
- Правило 1 требует именно *локализованного* имени (см. ниже); объект с именем
  только на непонятном языке имени не считается — он честно деградирует в
  правило 3/4.

## Enrichment «(рядом: …)»

Если в ≤ 150 м есть **landmark** — подпись главного объекта дополняется суффиксом
`(рядом: …)` / `(near …)`. Landmark должен удовлетворять всему списку:

- другое `osmId` (оба известны и различны);
- есть локализованное имя;
- kind входит в `LANDMARK_KINDS` (музеи, памятники, храмы, парки, мосты,
  фонтаны, смотровые, вокзалы… — список в `kinds.ts`);
- **не** postcode и не дорога;
- город совпадает, если известен обоим (`addr:city`; у одного неизвестен —
  пропускаем проверку, не запрещаем).

Из подошедших берём ближайший. Не энричим landmark'ом, чьё имя совпадает с
именем главного объекта (это тот же объект под другим osmId).

## Локализованное имя и шаблоны лейблов

**Имя объекта** (для локали L): `tags['name:' + L]` → `name` → ничего.
Имя на «не том» языке лучше пустоты: если `name:en` нет, а есть локальное
`name` — показываем его.

**Kind-подпись** — словарь `kinds.ts`: ~40 OSM-kind'ов → `{ ru, en, icon }`
(иконки lucide-react). Неизвестный/отсутствующий kind → нейтральная подпись
«Место / Place» и нейтральная иконка. Словарь знает и служебные kind'ы:
`house` (Дом / Building), `street` (Улица / Street), `postcode` (без подписи —
почтовый индекс именем места не показываем).

**Дедуп алиасов.** Если имя начинается с kind-слова — kind-подпись скрывается:
«памятник Пушкину», а не «памятник · памятник Пушкину». Нормализация сравнения:
lowercase, `ё → е`, пунктуация схлопывается в пробелы, сравнение по префиксу
с границей слов. Работает в обе стороны для суффикса «рядом»: landmark
«Памятник Пушкину» с kind `monument` в суффиксе пишется просто «Памятник
Пушкину», без слова kind.

**Адрес**: `address` → `addr:street` + `addr:housenumber` → ничего
(не выдумываем).

**Расстояние**: < 1000 м → «350 м» / «350 m»; ≥ 1000 м → «1,2 км» / «1.2 km».
Показывается для дистанции от точки прогулки до объекта.

## Часы работы — подмножество OSM opening_hours

Оценка `evaluateOpeningHours(raw, at, timeZone)` → `'open' | 'closed' | 'unknown'`.
Таймзона (IANA) передаётся **параметром** — одна и та же строка часов
оценивается в зоне точки прогулки, а не сервера.

Поддержано:

- `24/7`;
- `off`, `closed` — всегда закрыто;
- дни: `Mo-Fr` (диапазон, в т.ч. через границу недели `Fr-Mo`), списки `Sa,Su`,
  одиночные `Mo`;
- время: `HH:MM-HH:MM`, конец меньше начала = через полночь (`Sa 22:00-04:00`),
  `24:00` как конец (`Mo-Fr 09:00-24:00`); несколько диапазонов через запятую;
- список правил через `;`;
- правило без дней = все дни (`09:00-18:00`);
- правила-вычитания: `Tu off`, `Mo 12:00-14:00 off`.

**Не поддержано** (любое вхождение → весь результат `unknown`, никогда не
«закрыто»): месяцы, годы, номера недель, `PH`/`SH`, `sunrise`/`sunset`,
`+` (открыто «и дальше»), часы > 24 (`28:00`), секунды, переменные.
Правило, которое не разобрались распарсить, портит всю строку — частичная правда
в бейдже равна лжи.

Границы: открытие **включительно**, закрытие **исключительно** (в 18:00:00 при
`09:00-18:00` — уже закрыто). Нет `raw`, пустая строка, неизвестная таймзона →
`unknown`.

## UI

- **`PlaceCard`** — полная карточка: kind-иконка + подпись, имя, адрес,
  расстояние, бейдж open/closed/unknown (открыто — зелёный, закрыто — серый,
  неизвестно — нейтральный с текстом «часы неизвестны»), слот «почему сюда».
- **`PlaceMiniCard`** — якорная мини-карточка над картой: имя + kind + бейдж.
  Позиционирование через CSS-переменные (`--pc-x`, `--pc-y`) с **пиксельным
  clamp** внутри контейнера карты — хук `useAnchoredPosition` меряет карточку и
  контейнер и не даёт карточке вылезти за края. Мобильный вариант — bottom
  sheet с полной `PlaceCard` внутри; переключение чистым CSS (`md:` брейкпойнт),
  без JS media-запросов.
- Всё через пропсы; **зависимость от карт-библиотек запрещена** — адаптер
  «координата карты → пиксельный якорь» пишет интеграционный чат.
