# UX: главный экран «Прогуляться сейчас»

> Статус: дизайн v1, чат E (ворктри feat/ui-shell).
> Источник правды: `docs/PRODUCT.md` — здесь реализуются принципы **1–3**
> (прогулка без регистрации · один главный экран · локальная перестройка).
> Реализация: `next-app/src/components/walk/**` (визуал + интеракции на колбэках,
> без интеграции с движком и стором).

---

## 0. TL;DR

Карта на весь экран, одна шторка-карточка. Гость отвечает на два вопроса —
«сколько есть времени?» и «какой вайб?» — и получает живую карточку прогулки:
честный разбор времени, бейдж бюджета, таймлайн остановок с причинами и кнопкой
«заменить» на каждой. Всё остальное (адреса, поля, транспортные режимы) — в
эксперт-режиме, который остаётся как есть.

## 1. Роль экрана

Экран закрывает 80% визитов: «открыл с телефона → выбрал время → идёшь гулять».
Поэтому:

- **ноль обязательных полей** — стартовое состояние уже полностью готово к
  первому тапу, ничего вводить не нужно;
- **одна карточка** — нет табов, аккордеонов и «ещё одной формы»;
- **всё состояние видно сразу** — время, разбор, бюджет; человек не должен
  скроллить, чтобы понять, успевает ли он;
- **перестройка локальна** — замена остановки не пересобирает прогулку и не
  заставляет карту мигать.

Эксперт-режим (`RouteBuilderSidebar`) остаётся доступным отдельным входом и
этим документом не описывается.

## 2. Машина состояний

Фазы — конечный автомат; та же модель реализована чистой функцией
`walkMachine` в `src/components/walk/logic.ts`.

```
            PARAMS_TOUCHED
   ┌──────┐ ─────────────► ┌────────┐
   │ idle │                │ params │ ◄─────────────┐
   └──────┘ ◄───────────── └────────┘               │
      │  ▲        RESET         │                   │ PARAMS_TOUCHED
      │  └──────────────────────┤                   │ (из error)
START_BUILD                     │                   │
      ▼                         ▼                   │
  ┌──────────┐  BUILD_SUCCESS ┌───────┐              │
  │ building │ ─────────────► │ ready │              │
  └──────────┘                └───────┘              │
      │    ▲                    │   │                │
      │    └───── RETRY ────────│─┐ │ OFFLINE        │ OFFLINE
      │ BUILD_FAILED            │ │ ▼                │
      ▼                         │ │ ┌─────────┐     │
  ┌───────┐ ────────────────────┘ │ │ offline │ ────┼── ONLINE → resume
  │ error │                       │ └─────────┘     │    (idle/params/ready)
  └───────┘                       └─────────────────┘
```

| Фаза | Что на экране | CTA |
|---|---|---|
| `idle` (пусто) | приглашение + чипы, ничего не выбрано | задизейблена, с подсказкой |
| `params` | чипы, что-то выбрано | «Собрать прогулку» активна |
| `building` | скелетоны + статус на карте пунктир петли | «Собираем…» (busy) |
| `ready` | сводка прогулки + таймлайн | «Идти» + «Пересобрать всё» |
| `error` | внятная ошибка, параметры сохранены | «Попробовать снова» |
| `offline` | предупреждение + заморожен последний контент | CTA задизейблена |

Правила переходов:

- `OFFLINE` приходит из `idle / params / ready` и **запоминает** фазу, чтобы
  `ONLINE` вернул человека ровно туда, где он был (ничего не сбрасываем).
- Из `building` при обрыве сети уходим в `error` (сеть упадёт и как ошибка
  сборки): это единственная дверь из `building`, кроме успеха.
- `RESET` — только по явному «Пересобрать всё» (очищает и параметры).
- Ошибка **не** стирает выбранные чипы: retry обязан быть одним тапом.

## 3. Мобильный — прежде всего

Продукт встречает человека на телефоне (принцип сценария №1: «открыл с
телефона»). Отсюда жёсткие правила:

1. **Шторка снизу, карта — фон.** Панель занимает нижние ~45% экрана в
   состояниях `idle/params`, разворачивается до 85dvh в `ready` (нужно больше
   строк таймлайна). Ручка шторки — тап по любому «пустому» месту хедера
   сворачивает/разворачивает (паттерн уже есть в `RoutePanel`).
2. **Одна колонка, тапы ≥ 48 px.** Чипы — высота 44–48 px, кнопка CTA — 56 px.
   Никаких hover-зависимостей: всё состояние выразимо без ховера.
3. **Первый экран без скролла.** Заголовок, 2 группы чипов, CTA — всё влезает
   в 640 px высоты. Таймлайн появляется только в `ready`.
4. **safe-area.** Нижний отступ `env(safe-area-inset-bottom)` — как в
   `RoutePanel`.
5. **Порядок блоков = порядок вопросов:** время → вайб → кнопка. Ни один
   блок не требует ответа на предыдущий, но визуально ведём сверху вниз.

Десктоп: та же карточка, прижатая слева (420 px, как эксперт-панель), карта
справа. Контент и порядок идентичны мобилке — меняется только контейнер.

- Ожидание ≤ 1.5 с до первого контента; если дольше — прогресс-строка

  заходить» из формулы прогулки.

  возвращает к нему без повторного ввода.
- Текст ошибки приходит из движка (например, «не нашлось мест категории…»);
  если движок не дал объяснения — общий текст. Никогда не показываем сырой
  stack trace.
- Первичная кнопка — retry (частый сценарий), вторичная — «Изменить параметры»
  (возврат в `params` без сброса чипов).

- Offline **не отдельный тупик**, а оверлей-полоса над замороженным контентом:
  если у человека уже была готовая прогулка — она остаётся читаемой (принцип 5,
  честная деградация). Если он был в `idle/params` — видит чипы, но CTA
  задизейблена с тем же пояснением.
- При `ONLINE` полоса исчезает, фаза возвращается той же чистой функцией —
  ничего не пересобирается и не теряется.

## 5. Иерархия внимания

Что видит глаз первым, по состояниям (вес: 1 — первый взгляд):

| Состояние | 1 | 2 | 3 |
|---|---|---|---|
| `idle/params` | Заголовок «Прогулка рядом» | Чипы времени (самая крупная интерактивная группа) | CTA |
| `building` | Строка «Собираем…» | Скелетон структуры | Прогресс на карте |
| `ready` | Итог «64 мин» + бейдж бюджета | Тип «Петля» (рядом с итогом) | Таймлайн: имена → причины → «Заменить» |
| `error` | Заголовок ошибки | Объяснение | Retry |
| `offline` | Полоса «Нет сети» | Замороженный контент | — |

Обоснование типографики:

- Итог времени — `text-3xl font-bold`, единственное место с таким весом:
  ответ на главный вопрос «успеваю?» должен читаться с расстояния вытянутой
  руки (телефон в руке, солнце).
- Заголовки групп чипов — `text-xs uppercase tracking-wider text-slate-500`:
  подписи, а не контент; не конкурируют с чипами.
- Причины остановок — `text-sm text-slate-500`, имена — `text-sm font-semibold`:
  имя и время сканируются колонкой, причина дочитывается по желанию.
- CTA всегда внизу карточки (мобильная зона большого пальца) и всегда одна
  первичная: `brand-500`. Никогда не две залитые кнопки рядом.

## 6. Решения и обоснования

### 6.1 Тайминг-чипы: 30 / 60 / 90 / «Точно…»

- **Пресеты 30/60/90**, а не 15/60/120: PRODUCT.md называет «30 мин / час /
  полтора-два» как реальное распределение запросов; 90 покрывает «полтора-два»
  без четвёртого чипа. Три пресета + кастом — предел рабочей памяти для одной
  строки на мобилке.
- **«Точно…» вместо слайдера на первом экране**: слайдер — это точность,
  которой у человека нет («минут 40»); степпер ±5 мин в диапазоне 10–180
  появляется только после тапа на «Точно…» и не раздувает стартовый экран.
- Чипы — одиночный выбор (это бюджет генератора, а не настройка): второй
  выбранный чип времени — противоречие, а не мультивыбор.

### 6.2 Чипы вайбов

- Пять архетипов ровно из PRODUCT.md: Зелёная, Кофейная, Вечерняя, Дождь,
  Удиви меня. Никаких «ещё категорий» — вайб не справочник.
- **Одиночный выбор**, «Удиви меня» — вайлдкард: тап по нему снимает
  конкретный вайб (движок получает «микс без явного ядра»). Повторный тап по
  выбранному вайбу снимает его — «можно без вайба».
- Иконка + слово (иконка ускоряет сканирование, слово убирает двусмысленность
  иконки). Вайб не обязателен: CTA активна от одного времени.

### 6.3 Сводка прогулки

- **Тип** — бейдж «Петля» / «Из А в Б» рядом с заголовком: петля — значение по
  умолчанию для главного сценария (вышел и вернулся), тип A→B — исключение,
  о котором надо сказать явно.
- **Итог** = ходьба + стоянки, одним числом. Рядом разбор: «ходьба 24 ·
  стоянки 40». Это дословная формула PRODUCT.md («47 минут ходьбы + 20 минут
  в парке»).
- **Бейдж бюджета ±10%**: `success` («в бюджете ±10%»), если итог ≤ бюджет+10%;
  `warning` («+N% к бюджету»), если вышли за пределы. Недобор бюджета
  бейджем не наказываем — «с запасом» это хорошо (дословно из PRODUCT.md).
  Недобор не хвалим отдельным бейджем — не засоряем шапку.

### 6.4 Таймлайн остановок

- Каждый `StopRow`: иконка вида места → имя + чип стоянки → причина →
  «Заменить». Между строками — «N мин пешком» мелким текстом на пунктире.
- Порядок полей = порядок вопросов человека: «куда?», «надолго?», «зачем?»,
  «а если не понравится?».
- Причина — обязательная (гейт генератора: «≥ 2 якоря, у каждого — причина
  зайти»); в fixtures она всегда заполнена, пустых причин в UI не бывает.

### 6.5 Замена в один тап

- Кнопка «Заменить» прямо в строке — не в карточке остановки и не в меню:
  замена остановки — действие №1 после первого взгляда на план (принцип 3).
- Тап → строка локально превращается в мини-скелетон («Ищем замену…»),
  остальная карточка **не мигает**: это и есть «меняется сегмент, а не вся
  прогулка». Callback `onSwapRequest(stopId)` уходит наружу; в демо замена
  подставляется из пула альтернатив через ~0.9 с и подсвечивается.
- Замену даём только у остановок (у перегонов «N мин пешком» кнопки нет —
  перегон чинится выбором другого вайба/времени).

## 7. Движение и тайминги

| Событие | Анимация | Длительность |
|---|---|---|
| Появление шторки | translateY вверх + ease-out | 300 мс (как `RoutePanel`) |
| Выбор чипа | scale 0.97→1 + смена фона | 150–200 мс |
| `building → ready` | карточка: fade + подъём 8px; строки таймлайна — каскадом по 60 мс | 250 мс + каскад |
| Скелетоны | opacity pulse | 1.2 с цикл |
| Петля на карте | пунктир бежит (`animate-dash`) | постоянная, только в `building` |
| Замена строки | collapse 120 мс → мини-скелетон → expand 160 мс с подсветкой brand-50 | ~0.9 с до результата |

Все переходы выключаются при `prefers-reduced-motion` (остаётся мгновенная
смена состояний).

## 8. Доступность

- Чипы времени: `role="radiogroup"` + `role="radio"` + `aria-checked`;
  группа вайбов: `role="group"` + `aria-pressed` на кнопках.
- CTA в `building`: `aria-busy="true"`; скелетоны — `aria-hidden`, рядом
  визуально скрытый текст «Идёт сборка прогулки».
- Ошибка: контейнер с `role="alert"`; кнопки с понятными labels.
- «Заменить»: `aria-label="Заменить остановку «{имя}»"` — на таймлайне много
  одинаковых кнопок, name-only «Заменить» недопустим.
- Цели тапов ≥ 44×44 px; фокус — видимый ring `brand-500` (как в `Button`).
- Контраст: slate-500 по белому ≥ 4.5 для мелкого текста; бейджи — пары
  `*-100/*-700` из примитива `Badge`.

## 9. Тон копирайтинга

- Обращение на «вы» — нейтрально и коротко. Никаких «Ой!» и «Упс!».
- Обещаем только то, что делаем: «Ищем улицы, якоря и честное время».
- Ошибки объясняют причину и дают следующий шаг, но не извиняются троекратно.
- Числа — в человеческом формате: «1,5 часа», «64 мин», «+12% к бюджету».

## 11. Открытые вопросы

1. **Вайб — одиночный выбор.** Если движку захотят «Вечерняя + Дождь» (вечер
   под дождём), модель чипов меняется на мультивыбор с лимитом 2. Сейчас —
   ровно под архетипы PRODUCT.md (один архетип).
2. **Прогноз под CTA** («Петля от вас · ~30–40 мин») — считает фронт по бюджету;
   если движок даст точнее — заменить на его данные.
3. **«Идти»** — кнопка-плейсхолдер готовой карточки: пошаговый режим навигации
   вне скоупа (PRODUCT.md: не навигатор). Нужен продукт-решение, что она
   делает: экспорт в Яндекс.Карты / полноэкранный режим карточки / ничего.
4. **Геолокация.** Дизайн предполагает «вы здесь» от браузера; при отказе —
   та же `idle`-шторка + мягкая просьба выбрать стартовую точку (в эксперт-
   режиме это уже умеет карта). Отдельное состояние не вводилось.
5. **SketchCard** — эксперимент с hand-drawn рамкой на нативных SVG-фильтрах
   (`feTurbulence + feDisplacementMap`): `rough.js` не добавлял, чтобы не
   трогать `package.json` вне зоны файлов чата. Если стиль зайдёт — добавить
   зависимость и заменить фильтр на rough-рисование.
