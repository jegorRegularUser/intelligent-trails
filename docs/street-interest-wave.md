# Волна «Улицы с характером» — дизайн-док (данные + интерес + прогулка без якорей)

> Статус: правлен по холодной критике (2026-11-17): B1–B3, S4–S9, C10–C11
> внесены. Опирается на волну docs/walk-loop-quality.md (коридор бюджета,
> diversifyByAzimuth с 8 секторами, routeAlternatives в assemblePlan —
> имплементится параллельно). Контракт: docs/PRODUCT.md.

## Диагноз

Единственный якорь-независимый режим — L3 `streetLoop`: геометрическая роза
без единого запроса к данным (`streetLoop.ts:117-230`), слепая к среде.
Overpass-адаптер режет геометрию ways (`out center`, `overpass-places.ts:56-63`)
и отбрасывает безымянные элементы (`:110-111`); порт движка не умеет «путь с
притяжениями»; скоринг улиц отсутствует. Прогулка без чётких точек сегодня =
случайная геометрия.

## Целевое поведение

Движок узнаёт, где вокруг старта интересно гулять: зелень, вода, пешеходные
улицы, видовые точки, арт. Роза притягивается к этим зонам (снап стабилен
через tune-цикл радиуса); альтернативы ног выбираются с учётом интереса;
вдоль маршрута цепляются микро-стопы. Нет данных — прежняя геометрическая
роза (честная деградация сохраняется побитово: поля `undefined`, не пустые
массивы).

## S1. Данные: `src/lib/geo/streetFeatures.ts`

**Кап радиуса (B1)**: `fetchStreetFeatures(center, searchRadius)` —
`clamp(searchRadius, 500, 3000)` (без капа при бюджете 240 радиус был бы
7208 м и bbox 14+ км). Один Overpass-запрос, 5 классов фич union'ом.

**Клип (B1)**: statement-фильтр `[bbox:s,w,n,e]` для скорости + `out geom
(s,w,n,e);` — Overpass клипует геометрию вывода только этим параметром `out`
(bbox/around отбирают элементы, но возвращают их ПОЛНУЮ геометрию). Для
relation-мультиполигонов клип членов гарантирован не всеми версиями —
подстраховка клиентским капом.

**Клиентские капы (B1)**: elements > 3000 или суммарных точек > 50 000 →
частичная деградация (брать по приоритету классов: water/green/pedestrian,
потом viewpoint/art) или `null`. Свой `[timeout:20]` и отдельный клиентский
таймаут (делил бы `overpassMs: 12_000` с POI — недопустимо, `config.ts:45`).

**Децимация**: контуры ресемплятся до ≤64 точек сразу при нормализации
(ресемпл есть — `internal/geo.ts:74-99`); потребителям (буферы 60/80 м,
attractionPoint) хватает.

**Классы фич** (kind → OSM → геометрия):

| kind | OSM | Геометрия |
|---|---|---|
| green | `leisure=park`, `leisure=garden`, `natural=wood` | полигоны |
| water | `natural=water`, `waterway=riverbank/canal/stream` | полигоны/линии |
| pedestrian | `highway=pedestrian`+name, `place=square` | линии/полигоны |
| viewpoint | `tourism=viewpoint`, `man_made=viewpoint` | точки |
| art | `tourism=artwork`, `amenity=fountain`, `historic=memorial/monument` | точки |

**Парсер (C10)** — с нуля (существующий `elementPoint` с `out geom` не
работает: center при geom не отдаётся): node `{lat,lon}`; way `{geometry[]}`;
relation — брать **outer-кольца** members (`{members[].geometry}`, дедуп с
way-фичами). `waterway=riverbank` (area) vs canal/stream (линии) — парсеру
всё равно; «точка берега» для канала = ближайшая точка **осевой** линии —
допущение зафиксировать. Без имени — не отбрасывать (у воды/зелени имени
часто нет).

## S2. Интерес-модель: `src/lib/vibes/streetInterest.ts`

`scoreSectors(features, start, archetype) → StreetHints`:

- 8 азимутальных секторов — константа **`SECTOR_COUNT` в `src/lib/walk/types.ts`**
  (блок констант `:110-127`, файл без импортов — безопасен; S4). Азимут-хелпер
  — `internal/geo.ts` рядом с `localProjection` (`:35-42`).
- **Конвенция секторов — pinned-тест (S4)**: проекция даёт x=восток/y=север
  (`internal/geo.ts:40`), роза строит азимут от севера по часовой
  (sin→lat, cos→lng — `streetLoop.ts:107-114`) → сектор = `floor((atan2(x,y)
  mod 2π)/45°)`. Разъедутся на 90° — снап притянет вейпоинт в чужой сектор
  молча.
- **Присвоение фичи сектору — по вершинам (S4)**: большой парк накрывает 3
  сектора — вклад раскладывается по вершинам (каждая вершина — свой сектор);
  это же даёт честную attractionPoint.
- `interest(sector) ∈ [0..1]` = нормированная сумма вкладов: вес фичи = база
  по kind (water 1.2, green 1.0, pedestrian 0.9, viewpoint 1.5, art 0.7) ×
  архетипный множитель (archetypes.ts: green → green×1.6/water×1.3; coffee →
  pedestrian×1.4; evening → pedestrian×1.1 (lit-теги улиц вне волны); rainy →
  все ×0.3; surprise → без множителя; sightseeing → viewpoint×1.6/pedestrian×1.2)
  × близость к старту (мягкий, дальние меньше) × размер полигона (лог-шкала
  площади).
- `attractionPoint(sector)` — ближайшая к старту точка **контура** лучшей фичи
  сектора через `pointToSegmentMeters` (`internal/geo.ts:60-67`, уже есть) —
  вершины OSM-полигонов неравномерны (C10).
- Выход: `StreetHints { sectors: [{ azimuthDeg, interest, point }],
  hasData: boolean }`.

## S3. Умная роза (`streetLoop.ts`)

- **Снап — чистая функция `(sectorAngle) → point | null`, применяемая ВНУТРИ
  `buildWaypoints` на каждом вызове (B3)**: углы секторов от радиуса не
  зависят — снап стабилен между tune-шагами (tune перестраивает вейпоинты
  через `buildWaypoints` — `streetLoop.ts:98-115,186`; снап вне этой функции
  стёрся бы первым же ×1.3/×0.85). Радиус-джиттер (`streetLoop.ts:137`) на
  снапнутой точке игнорируется.
- Снап при `interest(s) ≥ INTEREST_SNAP_THRESHOLD (0.35)` и `hasData`;
  отклонение ограничено 30% радиуса (выше — геометрическая точка).
- **Дедуп attraction-точек (B3)**: один крупный парк в 2 секторах → два
  вейпоинта в одной точке → `loop_no_repeat_street` закономерно падает.
  Энфорс минимального углового разноса снапнутых вейпоинтов ≥
  `MIN_ANGLE_GAP_DEG` (`streetLoop.ts:27`, как в `buildShapeAngles`).
- **Ретрай на отказ route (B3)**: L3 живёт `route([start,...,start])`
  (`:157`), матрица НЕ участвует (поправка к черновику); отказ route с
  снапнутыми точками → один ретрай того же варианта с геометрическими
  вейпоинтами (кап `MAX_ROUTE_CALLS = 20` имеет запас); все варианты
  снапнуты и все отказали → честная деградация, не ошибка экрана.
- План с ≥2 снапнутыми секторами НЕ помечается `loop-only` degradation.
  **Без нового уровня `WalkDegradedLevel`** (закрытый union в двух местах) —
  опц. флаг `streetInterest?: true` на плане + заметка в стиле
  `DEGRADED_NOTES` (`uiAdapter.ts:39-48`, тексты ru/en в коде, sync-тест
  `uiAdapter.test.ts:115-127` — расширить схему). Текст этой волны,
  волна human design только рендерит: «Петля по характерным улицам района».

## S4. Микро-стопы «по пути»

- `WalkLeg.microNotes?: { name, kind, reason }[]` — точки kind
  viewpoint/art/вода-берег в буфере 60 м от полилинии ноги (после финального
  роутинга), ≤2 на ногу, отсорт по близости к пути.
- **Минуты считает движок ДО `evaluateGates` (B2)**: кап на план
  `Σmicro ≤ min(4, max(0, 1.1·B − totalMinutes))`; микро-минуты идут в
  totals как **walk**-минуты («шаг, взгляд»), не stay — иначе перевирается
  `walk_share` (`gates.ts:36-48`). Постфактум-добавление запрещено: карточка
  показала бы total > 1.1·B при gatesPass=true. Решение записать в
  walk-engine.md.
- Гейт `anchors` микро-стопы не засчитывают.
- **replaceStop и шеринг (S8)**: `replaceStop.ts:199` переиспользует ноги по
  ссылке — microNotes выживших ног остаются, пересобранных (k, k+1) —
  исчезают; НЕ пересылать microNotes в replace-экшен
  (`QuickWalkReplaceInput.currentLegs` остаётся `{walkMin, geometry}`);
  потеря при replace и в кодеке (`shareCodec` кодирует только stops) —
  задокументированная честная деградация, не баг.

## S5. Интерес в выборе альтернатив ног (мост от волны 1)

- Критерий (а) непересечение — первичен; тайбрейкер (б) дополняется долей
  полилинии альтернативы в буфере 80 м от green/water/pedestrian фич — при
  `hasData` и переданных фичах. Константа `ALT_INTEREST_BUFFER_M` — в
  `walk/types.ts` рядом с остальными.
- **Перф (C11)**: bbox-префильтр фич вокруг ноги + кап «топ-K фич по весу»
  (K=32) — иначе сотни полилиний × 64 точки × ~10-20 ног × ≤3 альтернатив
  станут самым дорогим шагом сборки.

## S6. Интеграция и типы (S5-критики)

- **Оба входа**: `WalkInput` (строгий движок) И `StreetLoopInput`
  (`fallback.ts:55-60` → `streetLoop.ts:55-62`) — L3 не получает WalkInput.
- **Слои**: `walk/types.ts` запрещает импорты lib/geo (заголовок `:1-5`) —
  структурные двойники `WalkStreetFeature { kind; geometry: WalkLatLng[] }`,
  `StreetHints` (прецедент `WalkPlace`, `types.ts:11-21`); конверсия на
  границе в quickPipeline.
- **Клиентская граница**: features/hints не покидают сервер; клиенту едет
  только `microNotes` (опц. поле `UiWalkLeg` в `components/walk/types.ts` —
  владелец поля эта волна; волна human design только рендерит) + флаг
  `streetInterest` для формулировки карточки.
- **Пайплайн**: параллельно POI-батчу — но **отдельным «батчем из 1» ПОСЛЕ
  последней категории с той же паузой (S7)**, не в общий `Promise.allSettled`
  (пик конкурентности 4 вместо 3 при ~2 слотах на IP — сценарий тихих
  потерь); в ретрай-волну не включать (упал → `null`).
- **Кэш (S6)**: свой `TtlLruCache` модуля (maxEntries ≤ 50 — payload на
  порядок жирнее placesCache; опц. метод на GeoProvider, ADR-001 разрешает
  расширение). Ключ `center(roundPoint)+radius`; TTL 10 мин (гасит повтор
  при замене остановки); **отрицательный кэш 60-120 с** — при лежке зеркал
  `fetchElements` жжёт 1 + Promise.any × 8 зеркал × 12 с, без него каждая
  сборка платит до ~24 с.
- **Инъекция fetch для тестов** — добавить метод в `OverpassPlacesAdapter`
  (переиспользовать зеркальную логику), не копипастить.
- **Деградация**: пустой `elements` = «данных нет» (hasData=false, как пустой
  POI-ответ `cloud-provider.ts:120`); при hasData=false поля WalkInput
  передавать `undefined`, не пустые массивы — иначе снапшот-тест деградации
  бит-в-бит не сойдётся.

## Порядок работ (S9)

1. `SECTOR_COUNT` + азимут-хелпер + pinned-тест конвенции.
2. `streetFeatures.ts`: запрос с клипом, парсер node/way/relation, кэш +
   отрицательный кэш, фейк-fetch тесты (паттерн `overpass-places.test.ts:34-60`).
3. `scoreSectors` + тесты.
4. Снап внутри `buildWaypoints` + ретрай + дедуп + тесты.
5. `microNotes`: типы обеих сторон, минуты до гейтов, uiAdapter + sync-тест.
6. S5-тайбрейкер с префильтром.
7. Интеграция quickPipeline + снапшот-тест деградации (планы при hasData=false
   идентичны текущим).

## Границы волны

`lit=yes` на улицах (дорого по квоте/размеру), graph-роутинг «через парк»
(мы притягиваем вейпоинты и выбираем альтернативы, не строим граф улиц),
эксперт-режим, фото/карточки (волна human design), i18n messages/*.json
(тексты этой волны живут в uiAdapter-коде ru/en; messages ведёт волна 3).

## Тесты (все оффлайн, фейк-фикстуры)

- pinned: конвенция секторов (роза↔проекция, 45°).
- `scoreSectors`: детерминизм, нормировка, архетипные множители, разложение
  по вершинам, пустой сет → hasData=false.
- парсер: node/way/relation-outer, мультиполигон с островом, дедуп members.
- клип/капы: bbox-параметр в запросе (строка-снапшот), капы elements/точек →
  частичная деградация, децимация ≤64.
- снап: отклонение ≤30%, порог интереса, дедуп MIN_ANGLE_GAP_DEG, стабильность
  между tune-шагами, ретрай на route-отказ.
- микро-стопы: буфер 60 м, ≤2 на ногу, минуты до гейтов (total не вылетает
  за 1.1·B), walk-минуты в totals, anchors не засчитывает, потеря при replace
  задокументирована.
- альтернативы: тайбрейкер интересности при равном непересечении, префильтр.
- деградация: StreetFeatures=null → планы идентичны текущим (снапшот,
  undefined-поля).
