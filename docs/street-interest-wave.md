# Волна «Улицы с характером» — дизайн-док (данные + интерес + прогулка без якорей)

> Статус: чернова́к. Контракт: docs/PRODUCT.md (формула: улицы, а не прямые
> линии; контекст; честная деградация). Опирается на волну
> docs/walk-loop-quality.md (коридор бюджета, альтернативы ног, repair-циклы).
> Диагноз — из разведки движка 2026-11-17.

## Диагноз

Единственный якорь-независимый режим — L3 `streetLoop`: геометрическая роза
без единого запроса к данным (`streetLoop.ts:117-230`), слепая к среде.
Overpass-адаптер умеет только точечные POI и **режет геометрию** ways/relations
(`out center`, `overpass-places.ts:56-63`); безымянные элементы отбрасываются
(`:110-111`). В порту движка нет примитива «путь с притяжениями»
(`ports.ts:32-37`); скоринг улиц отсутствует (`ranking.ts:145-250` — только
места). Прогулка без чётких точек сегодня = случайная геометрия.

## Целевое поведение

Движок узнаёт, **где вокруг старта интересно гулять**: зелёные массивы, вода,
пешеходные улицы, видовые точки, арт. Роза вейпоинтов притягивается к этим
зонам; альтернативы ног выбираются не только «непересекающиеся», но и
«проходящие через интересное»; вдоль маршрута цепляются микро-стопы
(«по пути: фонтан, вид на реку»). При отсутствии данных — прежняя геометрическая
роза (честная деградация не теряется).

## S1. Данные: `streetFeatures` (новый модуль `src/lib/geo/streetFeatures.ts`)

Один Overpass-запрос на сборку (в общий батч-окно `quickPipeline`), **`out geom`**
(не `out center`) с bbox-клипом по радиусу зоны:

| kind | OSM | Геометрия |
|---|---|---|
| green | `leisure=park`, `leisure=garden`, `natural=wood` | полигоны (контур) |
| water | `natural=water`, `waterway=riverbank/canal/stream` | полигоны/линии |
| pedestrian | `highway=pedestrian` +name, `place=square` | линии/полигоны |
| viewpoint | `tourism=viewpoint`, `man_made=viewpoint` | точки |
| art | `tourism=artwork`, `amenity=fountain`, `historic=memorial/monument` | точки |

Тип: `StreetFeature { id, kind, name?, geometry: LatLng[], tags }`. Без имени —
не отбрасывать (у воды и зелени имени часто нет, а притягивать они умеют).
Кэш — общий TTL-кэш провайдера; TTL как у POI. Размер ответа: радиус зоны
≤3 км, город — сотни KB, приемлемо; при таймауте/ошибке — `null` (не исключение),
все потребители деградируют.

Точки (viewpoint/art) попадают и в существующий точечный канал при
соответствующей категории — здесь дубль допустим, нормализация в
`streetFeatures.normalize()`.

## S2. Интерес-модель (`src/lib/vibes/streetInterest.ts`)

`scoreSectors(features, start, archetype) → StreetHints`:

- Сетка 8 азимутальных секторов вокруг старта (те же 8, что в диверсификации
  волны 1 — одна константа `SECTOR_COUNT`).
- `interest(sector) ∈ [0..1]` = нормированная сумма вкладов фич сектора:
  вес фичи = базовый по kind (water 1.2, green 1.0, pedestrian 0.9,
  viewpoint 1.5, art 0.7) × архетипный множитель (archetypes.ts: green →
  green×1.6/water×1.3; coffee → pedestrian×1.4; evening → pedestrian×1.1
  (lit-теги улиц — вне волны, см. §Границы); rainy → все ×0.3;
  surprise → без множителя; sightseeing → viewpoint×1.6/pedestrian×1.2).
  Близость к старту — мягкий множитель (дальние фичи весят чуть меньше),
  размер фичи — площадь полигона (лог-шкала).
- `attractionPoint(sector)` — репрезентативная точка лучшей фичи сектора:
  ближайшая к старту вершина/точка на контуре (для воды — точка берега:
  ближайшая точка полилинии к старту в этом секторе).
- Выход: `StreetHints { sectors: [{ azimuthDeg, interest, point }], hasData }`.

## S3. Умная роза (`streetLoop.ts`)

Для каждого вейпоинта розы (сектор известен — угол): если `hasData` и
`interest(s) ≥ INTEREST_SNAP_THRESHOLD (0.35)` — вейпойнт снапится к
`attractionPoint(s)`, отклонение ограничено `30%` радиуса розы (выше —
отказ снапа, остаётся геометрическая точка). Радиусы розы не меняются.
План в этом случае НЕ помечается `loop-only` degradation, если ≥2 сектора
снапнулись: у прогулки есть содержимое улиц. Формулировка карточки:
«петля по характерным улицам района» (новый ключ i18n).

## S4. Микро-стопы «по пути»

- `WalkLeg.microNotes?: { name, kind, reason, walkMinFromPath }[]` — точки
  kind viewpoint/art/waterfront в буфере 60 м от полилинии ноги (после
  финального роутинга), ≤2 на ногу, отсорт по близости к пути.
- В таймлайне — отдельная мелкая строка между ногами (UI-часть — с волны
  human design, здесь только данные + uiAdapter прокидывает).
- Гейт `anchors` микро-стопы не засчитывают (продуктовые якоря остаются
  содержательными местами); в `totals` время микро-стопов входит как 1 мин
  на заметку (шаг, взгляд — не сидение).

## S5. Интерес в выборе альтернатив ног (мост от волны 1)

`createWalkPlan.ts` выбор альтернативы: критерий (а) непересечение остаётся
первичным; тайбрейкер (б) дополняется: доля полилинии альтернативы в буфере
80 м от green/water/pedestrian фич — «интересность» (если StreetHints.hasData
и StreetFeatures переданы). Константа `ALT_INTEREST_BUFFER_M = 80`.

## S6. Интеграция в пайплайн

- `quickPipeline`: параллельно с POI-батчем — `fetchStreetFeatures(center,
  searchRadius)`; результат → `scoreSectors` → `WalkInput.streetHints` +
  `streetFeatures` (для S5/S4). Движок получает их через расширение `WalkInput`
  (опциональные поля — строгие тесты без фич не меняются).
- Деградация: `streetFeatures = null` → hints.hasData=false → роза
  геометрическая, микро-стопов нет, альтернативы выбираются по старым правилам.

## Границы волны

- `lit=yes` на улицах — вне волны (запрос по всем highway дорог по квоте/размеру;
  вечерний архетип пока опирается на POI-канал).
- Маршрутизация «через парк» как первоклассный примитив (graph-роутинг) —
  вне волны; мы притягиваем вейпоинты и выбираем альтернативы, но не строим
  собственный граф улиц.
- Эксперт-режим: не трогаем.

## Тесты (все оффлайн, фейк-фикстуры)

- `scoreSectors`: детерминизм, нормировка 0..1, архетипные множители,
  пустой фич-сет → hasData=false.
- `streetLoop` снап: отклонение ≤30%, отказ снапа за порогом, ≥2 сектора
  снимают `loop-only` метку.
- микро-стопы: буфер 60 м, ≤2 на ногу, не входят в гейт anchors, время 1 мин.
- альтернативы: тайбрейкер интересности при равном непересечении.
- деградация: StreetFeatures=null → планы идентичны текущим (снапшот-сравнение
  на фикстурах).
