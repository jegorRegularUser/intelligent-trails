# Intelligent Trails — продуктовая логика

> Этот документ — контракт на продукт. Любая фича сначала сверяется с ним.

## Главная правда о людях

Человек почти никогда не знает, куда хочет пойти. Он знает три вещи:
**сколько у него времени, какое настроение и где он находится.**
«Пойду в ТЦ, потом в кино, потом в парк» — редкий сценарий чёткого плана.
Сайт существует для остальных 95% случаев: **человек хочет прогуляться — сайт
придумывает прогулку, человек её утверждает и идёт.**

Мы не планировщик маршрутов между точками. Мы **генератор прогулок**.

## Три сценария входа

### 1. «Прогуляться сейчас» — главный, им закрывается 80% визитов
Открыл с телефона → выбрал время (30 мин / час / полтора-два) → выбрал вайб
(зелёная / кофейная / вечерняя / дождь / удиви меня) → **готовая петля от
текущей точки**. Ноль обязательных полей, ноль адресов. Гость — без регистрации.

### 2. «Новый город / чужой район»
Город или точка на карте + бюджет времени → обзорная петля по характерным
местам района. Место с историей и карточкой, а не пины «достопримечательность».

### 3. «А → Б, но красиво» — эксперт-режим (текущий функционал)
Человек знает начало и конец — движок подбирает по пути осмысленные остановки
и предлагает порядок. Здесь живёт весь ручной контроль: адреса, категории,
транспортные режимы.

## Формула прогулки (что именно строит сайт)

**Прогулка = реальный пешеходный маршрут (петля или A→B) по улицам, с 2–4
осмысленными остановками, уложенный в бюджет времени и подобранный под
контекст — время суток, погоду, сезон.**

Составляющие:

- **Улицы, а не прямые линии.** Геометрию и время считает серверный роутинг,
  а не догадки. Петля не проходит дважды по одной улице.
- **Остановки-якоря.** Не «категория кафе», а конкретное место: что это, зачем
  сюда заходить, работает ли сейчас, сколько тут сидеть. У каждой — альтернативы
  в один клик.
- **Честное время.** «47 минут ходьбы + 20 минут в парке = 67 минут, в твой час
  укладываешься с запасом». Бюджет — первое ограничение генератора.
- **Контекст.** Дождь → крытые точки; жара → тень и зелень; вечер → освещённые
  улицы и живые места; зимнее солнце → открытые виды.

## Принципы продукта

1. **Прогулка без регистрации.** Гость сразу получает результат. Аккаунт —
   только сохранение, история и избранное.
2. **Один главный экран.** Карта + одна карточка «твоя прогулка». Никаких форм
   из пяти полей.
3. **Локальная перестройка.** Не понравился двор → «другой вариант»; не
   понравилось кафе → «заменить». Меняется сегмент, а не вся прогулка.
4. **Ссылка = маршрут.** Шаринг в мессенджер открывает ту же прогулку.
   Локаль в ссылке не живёт — каждый читает на своём языке.
5. **Честная деградация.** Нет погоды или данных о тени — прогулка строится без
   них и сайт молча не обещает лишнего. Никогда не врём про то, чего не знаем.

## Сценарии-архетипы

Каждый архетип — это веса категорий + предпочтения indoor/outdoor + приоритет
тени/зелени + тайминги стоянок. Движок один, профили разные:

| Архетип | Ядро | Контекст |
|---|---|---|
| Зелёная | парки, скверы, набережные | тень/зелень важнее скорости |
| Кофейная | кафе, кондитерские, улочки | 1–2 сидячие остановки |
| Вечерняя | освещённые улицы, живые места | после 19:00, работает сейчас |
| Дождливая | музеи, галереи, ТЦ, крытые рынки | минимум улицы |
| Удиви меня | микс без явного ядра | максимум разнообразия якорей |

## Метрика хорошей прогулки (гейт генератора)

- укладывается в бюджет ±10%;
- ≥ 2 якоря, у каждого — причина зайти;
- нет сегмента длиннее ~25 минут без остановки;
- петля не возвращается по той же улице;
- каждая остановка работает/актуальна в момент прогулки.

## Не цели

- не навигатор (не ведём по шагам, не спорим с Яндекс.Картами);
- не соцсеть (без лент, подписок и комментариев);
- не справочник мест (карточка существует внутри прогулки, а не сама по себе).

## Универсальность территории

Сервис работает в любом городе с первого дня (облачные геоданные), а для
популярных регионов — «пакеты» собственного geo-стека как ускоритель.
Пользователь разницы не видит, кроме скорости и бейджа fast mode.
Подробно: архитектура geo-слоя описана в ADR geo-provider.
