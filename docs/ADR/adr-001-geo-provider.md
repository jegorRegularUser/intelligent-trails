# ADR-001: Geo-provider слой — два тира, один контракт

Статус: принят (2026-11-07). Контракт: `next-app/src/lib/geo/types.ts`.

## Контекст

Нам нужны: реальные пешеходные маршруты, карточки мест, зелень/тень, мгновенные
пересчёты — **в любом городе**, а не только в заранее подготовленном регионе.
Собственный geo-стек (пайплайн PBF → OSRM/Photon/PMTiles, обкатан в рабочем
проекте map-service) даёт скорость и данные, но привязан к региону.
Облачные сервисы универсальны, но медленнее и лимитированы.

## Решение

**GeoProvider — единый порт; два адаптера; выбор прозрачен для движка.**

| Тир | Реализация | Источники | Где работает |
|---|---|---|---|
| 1. Cloud | `CloudProvider` | Photon public / Nominatim (геокодинг), Overpass (POI), OpenRouteService foot (роутинг), Open-Meteo (погода) | любой город, с первого дня, без своего железа |
| 2. Pack | `PackProvider` | собственный стек: OSRM (foot) + Photon + PMTiles + POI-дамп в Mongo | популярные регионы; пайплайн уже написан |

Выбор адаптера: `isFastArea(start)` → если точка покрыта пакетом — PackProvider,
иначе CloudProvider. В UI это бейдж «fast mode», не переключатель пользователя.

## Правила слоя

1. **Контракт заморожен** (`types.ts`): расширяем новыми типами, не ломаем.
2. **Ошибки — только GeoError** со стабильными кодами (400/422/502/504-семантика).
   Деградация честная: нет данных → null/пусто, а не выдумка.
3. **Кэш обязателен**: ключи — координаты, округлённые до 5 знаков (~1.1 м),
   TTL + вытеснение. Пересчёт при драге точек не должен бить в сеть.
4. **Апстримы не доверяем**: ответ парсится строго, мусор → `UPSTREAM_INVALID`,
   таймауты явные (connect ~1s, read ~10s), без ретраев на POST.
5. **Единицы**: метры и секунды; координаты в API везде `[lat, lng]`.
6. Тесты — на фейковых апстримах (инъекция fetch); живые integration-тесты —
   отдельным файлом `*.integration.test.ts` (CI их исключает).

## Чего сознательно не делаем

- Не строим тень/зелень на этом слое — это скоринг поверх маршрута (ESA
  WorldCover + OSM landcover), отдельный модуль.
- Не храним POI в Mongo на облачном тире — Overpass + кэш достаточны;
  Mongo-дампы появятся вместе с PackProvider.
- Не отдаём клиенту ключи серверных провайдеров; всё через server actions.

## Последствия

- Движок прогулки (Фаза 2) тестируется на фейковом GeoProvider — оффлайн и детерминированно.
- Подключение региона-пакета = прогон пайплайна + строка в bbox-таблице, ноль правок движка.
- Миграция на MapLibre (Фаза 5) использует PackProvider'овские PMTiles.
