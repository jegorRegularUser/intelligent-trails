# ADR-004: OSRM (FOSSGIS) — фолбэк и безключевой первичный роутер

Статус: принят (2026-11-17). Контекст: ADR-001, docs/geo-cloud-design.md.

## Контекст

Единственный роутер облачного тира — OpenRouteService foot (ADR-001, тир 1).
Текущий ключ забанен провайдером (403 на все запросы), ферма ключей пуста —
продукт живёт без пешеходного роутинга. FOSSGIS OSRM `routed-foot`
(routing.openstreetmap.de) — публичный инстанс без ключа и без квоты, им
пользуется сам openstreetmap.org; он же заявлен тиром 2 (PackProvider) —
адаптер к нему нужен в любом случае.

## Решение

`OsrmRoutingAdapter` (`src/lib/geo/cloud/osrm.ts`) — те же два примитива, что у
ORS: `route(waypoints) → RouteSegment` и `matrix(sources, targets) → MatrixCell[]`.

Политика в `CloudProvider`:

1. **Ключа ORS нет (пустой/не задан) → OSRM ПЕРВИЧНЫЙ.** Продукт работает без
   ключей вообще; ORS не дёргается вовсе.
2. **Ключ есть → ORS первичный.** На его отказ `NO_ROUTE` /
   `UPSTREAM_UNAVAILABLE` / `UPSTREAM_INVALID` (403/429/5xx/мусор) — **одна**
   фолбэк-попытка OSRM. Ошибка фолбэка, если случится, уходит наверх вместо
   ошибки ORS (последняя попытка решает). `UPSTREAM_TIMEOUT` фолбэк не
   триггерит: это наш клиентский бюджет, время уже съедено, повторная попытка
   удвоила бы латентность.
3. Матрица и routeAlternatives — та же политика; OSRM альтернатив не строит,
   `routeAlternatives` деградирует в `[основной]` — легальная деградация
   контракта R3 («альтернатив нет, маршрут есть»).

Сегменты от OSRM помечаются `source: 'osrm'` (расширение литерал-union в
types.ts — аддитивное, потребителей значения нет: движок носит свой структурный
`source?: string`, бейджей поверх значения сейчас не существует).

## Fair use публичного инстанса

FOSSGIS — общественный ресурс: таймаут 15 с на запрос, **не более одного
запроса в полёте на примитив** (простая очередь `SerialQueue`, отдельная на
route и на matrix), **ретраев нет** — свои TTL-LRU-кэши и мемо-порт волны 1
режут повторы. Чанки матрицы режутся по бюджету длины URL (~8000 символов,
GET-эндпоинт), а не фиксированным числом точек, как у ORS (POST).

## Нюансы API (проверено живыми запросами 2026-11-17)

- Координаты в пути и в геометрии — `[lng, lat]`; при маппинге порядок
  переворачивается в обе стороны.
- Table-эндпоинт этого инстанса принимает параметр **`destinations`**, а не
  `targets`: с `targets=…` отвечают 400 InvalidQuery (старое имя параметра).
- Недостижимые ячейки таблицы — `null` → `MatrixCell` с `null`/`null`.
- Отказ при HTTP 200 сигнализируется `code` в теле: `NoRoute`/`NoSegment` →
  `NO_ROUTE`, прочие → `UPSTREAM_INVALID`.

## Последствия

- Роутинг переживает бан ключа ORS и отсутствие ключей; деградация без ключей
  исчезла как состояние.
- Публичный инстанс — не SLA: при его лежке остаётся честный GeoError; для
  гарантий — self-hosted OSRM через `OSRM_BASE_URL` (env-оверрайд, как ORS_BASE_URL).
- Пайплайн PackProvider (тир 2) сможет переиспользовать `OsrmRoutingAdapter`.
