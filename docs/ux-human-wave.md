# Волна «Human design» — дизайн-док (карта, вход, честность)

> Статус: чернова́к к реализации. Контракт: docs/PRODUCT.md (принципы 1–5),
> docs/ux-main-screen.md (спецификация главного экрана). Диагноз — из
> UX-разведки кода 2026-11-17.

## Диагноз

Главный сценарий закрыт лендингом (`/` → маркетинг → CTA → `/map`); мобильная
шторка не рендерит контент до тапа и бинарна по высоте (`RoutePanel.tsx:16,57,93`)
вместо 45%→85dvh из спеки; у быстрой прогулки нет шаринга (принцип 4 «ссылка =
маршрут» не работает); карта в `building` мертва и полностью перерисовывается
на каждой замене/листании вариантов (`fitNonce` → пересоздание пинов +
`setBounds`); пины — стоковые пресеты Яндекса; причина теряется в карточке пина
(`RouteMap.tsx:17-44`); причины в таймлайне — язык скоринга («Кофейня · Лучший
„кафе“ поблизости»); отказ геолокации объясняется как общая поломка;
`AddressInput` молчит при ошибке геокодера; «Новый город» — переименованный
быстрый режим без пикера города; при недоступной погоде сайт утверждает
«Погода располагает к прогулке» — враньё по принципу 5.

## Решения (зафиксировать до кода)

- **Стек карты**: maplibre-gl для главного сценария (quick / sightseeing /
  пикер точек / dev-демо карточек). Эксперт-режим **временно остаётся на
  Яндексе**: его метрики и транспортные альтернативы живут в рантайме
  `multiRouter.MultiRoute` (`RouteMap.tsx:224-303`) — ре-платформа транспортного
  роутинга вне этой волны. Два стека сосуществуют осознанно; ADR-заметка в
  `docs/ADR/adr-003-maplibre.md`, roadmap-пункт «ре-платформа эксперт-роутинга».
- **Тайлы**: OpenFreeMap (без ключа): стиль `positron` — спокойная подложка,
  на которой брендовая петля читается. `STYLE_URL` — одна константа
  (`src/components/map/maplibre/style.ts`). Фолбэк при недоступности — raster
  `CARTO positron` (атрибуция по лицензии). Атрибуция OpenFreeMap/OSM —
  обязательна в контроле.
- **Вход**: `/` = главный экран (карта + панель, дефолт-режим «Быстрая
  прогулка»). Лендинг целиком уезжает на `/about` («Как это работает» —
  ссылка в шапке панели и футере). Продуктовый принцип «открыл — выбрал
  время — идёшь» выполняется с первого экрана.
- **Шторка (мобайл)**: фазы `idle/params` → 45dvh с видимыми чипами времени;
  `ready` → 85dvh; контент рендерится всегда (убрать условный unmount
  `RoutePanel.tsx:93`); тап по ручке/свайп — свёрнутая/развёрнутая; safe-area
  сохраняется.
- **Фотографии мест**: в этой волне НЕТ. Принцип `docs/place-cards.md:19`
  не пересматриваем; красоту даёт карта (линия, пины, камера) и карточки
  (иконка+цвет+причина+часы+дистанция). Фото = внешний источник изображений —
  отдельное решение, вне волны.

## M1. Карта на maplibre (рендер главного сценария)

Файлы: новый `src/components/map/maplibre/MapCanvas.tsx` (ядро), хуки
`useMapRoute.ts`, `useMapPins.ts`; `RouteMap.tsx` для expert не трогается.
`RouteMapLoader` продолжает `dynamic(ssr:false)` — под ним теперь MapCanvas
для главного сценария, старый RouteMap — только для expert.

- **Линия маршрута**: GeoJSON source + line layer: кэш-слой (белая, 9px, 0.9) +
  основной (brand-600, 6px) + `line-dasharray` пульс на хвосте последнего
  сегмента? — нет, пульс только в `building` (см. ниже). Стрелки направления —
  symbol layer с дешёвым маркером-шевроном вдоль линии (опционально, если
  payload допустит).
- **Пины**: HTML-маркеры: старт — брендовый кружок с иконкой Footprints;
  остановки — номер в брендовом кружке + иконка вида места (те же 9 lucide);
  юзер — обычная точка. Карточка пина — `PlaceMiniCard` как сейчас, но с
  `reason` (данные уже в сторе) и стоянкой.
- **Камера**: `fitBounds` с padding `{left: 460}` (десктоп) / `{top: 40,
  bottom: панель}` (мобайл), `pitch 0`, длительность 800мс ease. При замене
  остановки / листании варианта — **обновление данных source и позиции пинов
  БЕЗ fitBounds** (камера переезжает только при новом плане/варианте, и то
  лениво: если новый вариант в пределах текущего вьюпорта +20% — не двигать).
- **Building-фаза**: на карте рисуется «набросанная» пунктирная петля-заглушка
  (окружность радиуса зоны от старта, `line-dasharray`, мягкая анимация dashoffset
  через CSS) — «думаем, куда тебя поведём». По успеху заменяется реальной линией.
- **Пикер точек**: клик по карте → координата (как сейчас на Яндексе).
- **Удаление Яндекса из главного сценария**: `@pbe/react-yandex-maps` остаётся
  в deps (expert), `package.full` грузится только на expert-вкладке — проверить,
  что ленивый импорт не тянет скрипт на `/`.

## M2. Вход и первый экран

- `src/app/page.tsx` → рендерит главный экран (маппинг текущего `/map`);
  `src/app/map/page.tsx` → `redirect('/')`; лендинг → `src/app/about/page.tsx`.
- Шапка панели: режимы-табы остаются, слева название, справа «Как это работает»
  (→ `/about`).
- Метаданные/SEO: title/description правятся на «Генератор прогулок…»,
  лендинг остаётся доступным для внешних ссылок.

## M3. Мобильная шторка по спеке

`RoutePanel.tsx`: высоты фаз 45/85dvh; контент монтирован всегда (скрыт
transform'ом); свайп-жесты ручки (pointer events, порог 24px); чипы времени
видны в `idle` без раскрытия.

## M4. Шаринг быстрой прогулки (принцип 4)

- `shareCodec.ts`: расширить кодек для быстрого плана (петля/A→B уже
  поддерживаются — проверить форму UiWalkPlan; параметры: stops, legs, totals,
  variantIndex). URL `/?w=<payload>` (главный экран теперь `/`).
- `WalkSummaryCard`: кнопка «Поделиться» (icon Share2) рядом с «Сохранить»:
  Web Share API → clipboard fallback → тост «Ссылка скопирована». Без логина.
- Открытие `/?w=` — стор гидратируется из URL, фаза `ready`, без сети.

## M5. Человеческий язык причин

- `reasons.ts` ревизия: формулы без тавтологий — причина не повторяет категорию
  («Лучший „кафе“ поблизости» при категории «Кофейня» → «Лучший выбор рядом» /
  конкретика «за углом, 2 мин»). Скоринговые чипы → человеческие формулы
  («тихий двор», «вид на воду», «открыто до 22:00»).
- `StopRow`: рендер «причина» без префикса категории, если причина уже
  человекочитаемая (маркер в данных).
- Карточка пина на карте: причина + стоянка + часы (данные есть в сторе).

## M6. Честные состояния

- Геолокация отклонена → «Не дали геолокацию — скажите, откуда пойдём» +
  фокус на адресном поле (error-код из `getCurrentStart`, новый i18n-ключ).
- `AddressInput`: ошибка геокодера — инлайн-текст под полем, не console.error.
- Погода неизвестна → «Погода неизвестна — идём в любую» (нейтральный факт,
  не позитивное утверждение).
- «Новый город»: настоящий пикер города через существующий suggest
  (`src/actions/suggest.ts`) — поле «город» устанавливает старт-центр;
  подзаголовок обещает ровно то, что делает.

## M7. Деградация и границы

- Тайлы не загрузились: карта серая с сообщением-плашкой «Карта недоступна —
  прогулка построена, смотри таймлайн» (движок не блокируется картой).
- maplibre не поддержан браузером (давние WebGL): фолбэк — старый Яндекс-рендер
  НЕ держим; показываем таймлайн-первый режим (карта скрыта, панель на весь
  экран). Редкий случай, фиксируем комментарием.

## Тесты и верификация

- Кодек `/?w=`: раундтрип (петля/A→B, пустые причины, utf-8) — vitest.
- Шторка: машина высот — чистые функции с тестами.
- Мап-рендер — ручной смоук через dev-сервер + скриншоты (visual judge):
  пустая карта / building с пунктиром / готовая петля с пинами и карточкой /
  мобильная шторка 45% / замена остановки без мигания.
- Существующие 499 тестов зелёные; `npm run build` проходит.

## Не делаем в этой волне

Тёмная тема (roadmap; вечерний вайб работает на светлой карте), фото мест,
ре-платформа эксперт-роутинга, ре-платформа suggest (Photon-фолбэк уже есть),
i18n новых локалей.
