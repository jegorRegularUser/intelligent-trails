# Волна «Прогулка, а не кратчайший путь» — дизайн-док

> Статус: правлен по холодной критике (2026-11-17): блокеры 1–4 и should 5–18
> внесены. Контракт: docs/PRODUCT.md (формула прогулки, метрика из 5 гейтов).
> Волна разворачивает целевую функцию существующего движка; уличный
> интерес-слой — следующая волна (docs/street-interest-wave.md).

## Диагноз (из разведки кода, 2026-11-17)

Бюджет в движке — **только потолок**: жадный набор останавливается при
`1.1·B` (`createWalkPlan.ts:375-393`), механизма добора до пола `0.9·B` нет;
`walk_share` и недобор ловятся гейтами, но гейты только помечают
(`gates.ts:34-63`). Воронка проксимити-формы на каждом этаже: радиус `0.4·B`
(`quickPipeline.ts:37-40`) → Overpass «N ближайших на категорию»
(`overpass-places.ts:220-223`, клиентский sort+slice) → скор со штрафом
`−proximity/zone` (`selection.ts:57-62` и дубль в `createWalkPlan.ts:327`) →
жадный набор в этом порядке. Порядок обхода — NN+2-opt на минимум времени
(`ordering.ts:29-97`); при равных скорах варианты сортируются в пользу
*короткого* плана (`createWalkPlan.ts:183-188`). Ноги — кратчайшая сшивка
(`route([a,b])`, `createWalkPlan.ts:433-441`); `alternatives` в
`RouteRequest` (`geo/types.ts:42`) адаптером не реализован и движком не
используется. Движок честно строит **короткий замкнутый тур по ближайшим
местам**; продукт обещает **прогулку**, уложенную в бюджет, — не минимальную.

## Целевое поведение

Бюджет — **коридор** 0.9–1.1·B: недобор закрывается добором остановок и
удлинением ног, потолок — жёсткий инвариант и на матрице, и на реальных
метриках. Кандидаты — по ценности с азимутной диверсификацией. Длинные ноги —
не одним кратчайшим маршрутом, если есть непересекающаяся альтернатива.
Гейты после ремонта честно видны в UI.

## R1. Коридор бюджета

### R1.a Порядок шагов сборки (внутри `assemblePlan`, `createWalkPlan.ts:427-516`)

Ноги (с альтернативами, R3) → проверка пола → добор остановками (R1.b) →
via-удлинение (R1.c) → итоги → скор → причины → гейты → выбор между
зеркальным обходом (`createWalkPlan.ts:418-424,521-533` — зеркало строится
такой же цепочкой; `fillToFloor` применяется к обоим до сравнения).
`fillToFloor` живёт в строгом движке; **L2 (`loopThrough`) и L3
(`streetLoop`) добором не трогаются** — «что есть, то есть», честная
деградация (`loopThrough.ts:200-201`). Соответственно `walk_share`-ремонт
действует только на строгие планы.

### R1.b Добор остановками

После финальных ног, если `totalMinutes < FLOOR_SHARE·B` (новая константа
`0.9` в `types.ts`, рядом с `BUDGET_TOLERANCE`):

1. Взять следующего по скору кандидата из пула, соблюдая **ту же политику,
   что у жадного набора**: `maxStopsForBudget(budget)` (4/6/8,
   `createWalkPlan.ts:283-287`) — не голый `MAX_STOPS` — и gap-проверку
   `minGapMeters`/`farEnough` (`createWalkPlan.ts:366-373`), иначе добор
   вернёт «три точки в квартале».
2. **Оценка по матрице с запасом**: кандидат влезает, если матричная оценка
   нового total ≤ `1.1·B − SAFETY_MARGIN` (`SAFETY_MARGIN = 0.05·B` — константа
   с мотивом: матрица и реальные ноги расходятся, это ловит гейт `budget`,
   `gates.ts:50-63`). Вставка остановки создаёт ДВЕ ноги из одной — оценка
   через матрицу этих двух плеч.
3. После каждого добора — пересборка ног и честный бюджет; если реальный
   total вылетел за `1.1·B` — откат последнего добора и стоп (потолок —
   инвариант §12 walk-engine.md).
4. Если пул исчерпан — переход к R1.c.

### R1.c Via-удлинение ноги

Если кандидатов нет: взять длиннейшую ногу (≤ `MAX_LEG_MINUTES − 2` мин —
иначе пострадает гейт `long_legs`, `gates.ts:79-88`), построить
`route([a, via, b])`:

- целевое удлинение `Δ` — недостающие минуты × **фактическая скорость плана**
  `Σdistance/Σminutes` (реальные ноги несут кривизну улиц и профиль ORS;
  константа 4.5 для оценки зоны, не для этого);
- офсет перпендикуляра `h = √(Δ·(2D+Δ))/2` (для Δ≪D ≈ √(ΔD/2); наивный
  «сместить на Δ» даёт прибавку ≈ 2Δ²/D — промах в разы), далее tune-цикл
  как в `streetLoop.ts:170-200`: GROW/SHRINK с капом ≤3 попыток на ногу;
- `route([a,via,b])` бросил NO_ROUTE → исходная нога сохраняется, пробуется
  следующая нога (не бросать наверх);
- гейт `loop_no_repeat_street` обязан пройти (via может замкнуть «туда-обратно»);
- ≤2 via-ног на план; stay не задваивается — меняются только ноги (записано
  явно, чтобы не искать баг).

### R1.d Честный отказ и вторая волна

Не дотянули — план возвращается как есть; gateReport показывает недобор в
`detail`. Фиктивные минуты запрещены. Добор живёт внутри пула; **эскалация
пула — на action-уровне**: `quickWalk.ts` после сборки проверяет чистый
предикат `isUnderfloor(plan, budget)` (экспортируется, тестируется) и, если
вторая волна ещё не гонялась, повторяет `collectCandidates` с
`SECOND_WAVE_MULTIPLIER` (`quickPipeline.ts`) и пересобирает (≤1 эскалация
на сборку). `createWalkPlan` про Overpass не знает — граница слоёв
сохраняется.

## R2. Воронка без проксимити-перекоса

- **Скор**: член `−proximity/zone` теряет доминирование — вес
  `PROXIMITY_WEIGHT = 0.25` (константа с мотивом) в **общей функции**
  `candidateScore(place, weight, rating, proximity, zone)` — единая формула
  для двух call-site: `selection.ts:57-62` и вариантный скор
  `createWalkPlan.ts:327` (иначе базовый отбор и вариантный разъедутся).
- **Азимутная диверсификация**: чистая функция
  `diversifyByAzimuth(entries, start, cap, sectorCount=8)` — применяется в
  `quickWalk.ts:115` **до** `slice(0, ENGINE_CANDIDATE_CAP)` (нарезка живёт
  в экшене, не в `scoreCandidatePool`; её семантика для `replaceStop`
  не меняется). Азимут по equirect-проекции (есть `localProjection`,
  `internal/geo.ts:35`). `SECTOR_CAP = 6` на сектор. Отбор секторов ведётся
  по кандидатам, влезающим в **минимальную из зон вариантов** — иначе сектора
  зальют шорт-лист кандидатами, которых движок тут же отсечёт по зоне
  (`selection.ts:56`), и узкий вариант умрёт NO_CANDIDATES. Пул замены
  (`quickWalkReplace.ts:177`) диверсифицируется тем же способом до
  `REPLACE_CANDIDATE_CAP`.
- **Overpass-лимиты**: `limit` per-category 12 → 20 — и вместе с ним
  `MIN_RESULTS_PER_CENTER` / `MIN_RESULTS_TOTAL` (`overpass-places.ts:18-20`)
  поднимаются/параметризуются, иначе в плотном городе эскалация всё равно
  остановится на 8–12 и изменение будет no-op.

## R3. Ноги с альтернативами

### R3.a Контракт ORS (по докам ORS, проверено критикой)

`alternative_routes` работает **только на запросах из 2 координат** (легы —
ок), `target_count ≤ 3`, дистанция ≤100 км; при невозможности удовлетворить
параметры ORS отвечает **HTTP 400 с кодом 2011**, а не пустым FeatureCollection;
фич может вернуться меньше `target_count` (issue #2475). Отсюда:

- `ors.ts`: при `alternatives > 0` и 2 вейпоинтах — body
  `alternative_routes: { target_count, share_factor: 0.6, weight_factor: 1.3 }`
  (weight_factor явный — дефолт не гарантирован);
- парсинг: цикл по всем features (текущий `parseGeojsonRoute` берёт
  `features[0]`, `ors.ts:80-112`) — новый путь для multi-feature ответа;
- **деградация = «альтернатив нет», не NO_ROUTE**: 400/2011, одна фича,
  пустой массив — лег строится обычным `route`; наверх не бросается;
- **кэш-ключ включает alternatives**: `route:{wps}:{alternatives}`
  (сейчас `cloud-provider.ts:91` ключ без него — первый ответ закэшируется
  для всех);
- интеграционный тест на 2011 и fewer-features через фейковый fetch
  (`src/lib/geo/__tests__`);
- перед имплементацией проверить дефолт `orsBaseUrl`
  (`config.ts:66` = `api.openrouteservice.org`; анонс миграции на
  `api.heigit.org`) — сверить лимиты/совместимость, поправить дефолт или
  подтвердить env-переопределяемость.

### R3.b Порт и кэш

- `ports.ts`: опциональный `routeAlternatives?(req): Promise<RouteSegment[]>`
  (основной первым). **memoPort обязан пробросить его** (`memoPort.ts:41-83`
  возвращает литерал `{route, matrix}` — без проброса фича мертва на всех
  продовых call-site): отдельный кэш-ключ `waypoints + alternatives`,
  дисковый слой — новый kind `route-alt`. Тест passthrough в memoPort-тесте.
- `portDiskCache.ts`: kind `route-alt`, TTL как у route (30 дней).

### R3.c Выбор альтернативы в движке

- Единственный локус вставки — цикл сборки ног в `assemblePlan`
  (`createWalkPlan.ts:433-457`): для ног > `LEG_ALT_MIN_MINUTES = 8`
  (константа в `types.ts`) запросить альтернативы (≤3 total). Выбор:
  (а) минимум пересечения с уже принятыми ногами —
  `fractionWithinCorridor` (`internal/geo.ts:106-126`);
  (б) при равном пересечении — самый длинный, влезающий в потолок `1.1·B`;
  (в) нет метода порта/альтернатив — основной.
- `routeVariant?: 'alt'` — **опциональное поле `WalkLeg`** (`types.ts:53-60`),
  не GateReport (тот по гейту). `replaceStop` реиспользует ноги по ссылке
  без изменений (`replaceStop.ts:84-87,199`); trio-матрица не затрагивается.
  Зафиксированный побочный эффект: перестройка замены вернёт основной
  маршрут (альтернативная геометрия не переживает replace) — приемлемо.
- `replaceStop.buildLeg` (`:306-332`), `loopThrough.ts:127-162`,
  `streetLoop.ts:155-199` остаются на простом `route`.
- **Квота**: `alternative_routes` возвращает ≤3 маршрутов одним
  directions-запросом — это 1 запрос на ногу, не 3. Арифметика сборки:
  1 matrix (25×25 = 625 ячеек, в лимите 3500/запрос) + ~10–20 directions
  (≤9 ног, мемо-порт режет дубли, диск гасит повторные районы) ≈ 60–100
  сборок/день на free-ключ. Общий кап на сборку `MAX_ROUTE_CALLS = 24`
  (как `loopThrough.ts:29`/`streetLoop.ts:48`) — счётчик вызовов через порт;
  сверх капа — обычный `route`. Дневной счётчик на ключ в `OrsKeyPool` —
  roadmap (сейчас реакция на 403/429 ретроактивна).

## R4. Гейты-ремонт

Ремонт = R1 (добор увеличивает и ходьбу, и total). Отдельного цикла нет.
Всё, что не дотянуто, — честно упавшие гейты (как сегодня).

## R5. Честность в UI

- `uiAdapter.ts`: аддитивное опциональное поле `UiWalkPlan.gatesSummary:
  { name; pass; detail? }[]` (плоский массив; `replaceStop.ts:30-35`
  перестаёт терять их; `shareCodec` кодирует только stops — раундтрип не
  задет; старые/расшаренные планы без поля — рендер деградирует guard'ом).
- `WalkSummaryCard`: при провале — одна строка-заметка человеческим языком
  (недобор: «прогулка вышла короче плана: рядом мало мест»; walk_share:
  «много сидения, мало ходьбы»). Строки синхронизировать с
  `uiAdapter.test.ts:130-139` (там сверяются словарные тексты деградации) —
  новые ключи считаются в этой схеме.
- База фолбэка замены честная: `quickWalkReplace.ts:63` шлёт
  `currentGatesPassed` — клиент может считать её из `gatesSummary` вместо
  хардкода «петля = 4».

## R6. Техдолг по пути

- `internal/geo-utils.ts`: `isFiniteLatLng / validateInput / errMessage` —

  `loopThrough.ts:272-302`, `streetLoop.ts:277-303`; errMessage в

- `quickPipeline.ts:38`: литерал скорости → `DEFAULT_WALKING_SPEED_KMH`.
- Зона: `zoneMetersForBudget(budgetMin, speedKmh)` в `internal/geo.ts`;

  R2-диверсификации она же даёт «минимальную зону вариантов». Формула
  прежняя — консолидация, не смена чисел.

## Тесты (vitest, фейковый grid-city порт)

- `fillToFloor`: плотный пул (раскладку узлов зафиксировать в тесте: при 60 мин
  зона ≈900 м, сетка даёт 5–9 кандидатов; кейс «55 мин при бюджете 60» →
  итог в [54,66]); пул исчерпан → честный недобор с gateReport, без фиктивных
  минут; откат добора при выходе реального total за `1.1·B`.
- Политика добора: `maxStopsForBudget` и gap не нарушаются.
- Via: офсет-математика (юнит на `h = √(Δ(2D+Δ))/2`); NO_ROUTE на via →
  исходная нога сохранена; гейт `loop_no_repeat_street` отсекает
  via-туда-обратно; cap ≤3 tune-попыток.
- Альтернативы: gridCity-фейк реализует `routeAlternatives` (Г-путь через
  `(a.lat,b.lng)` и его зеркало через `(b.lat,a.lng)` — перекрытие 0) →
  выбран непересекающийся; **частичные перекрытия 0.3–0.7 — юнит на
  синтетических полилиниях без порта**; memoPort passthrough + ключи диска;
  фейковый fetch: 2011 → «альтернатив нет», fewer-features, кэш-ключ с
  alternatives.
- Диверсификация: пул «20 лучших в одном секторе, 8 в других» → шорт-лист
  содержит ≥2 сектора; влезание в минимальную зону.
- `loopCoverage`: **сначала выпуклая оболочка, потом shoelace** (по сырой
  полилинии — знаковая алгебраическая площадь, на «восьмёрке» схлопнется);
  термин включается только при `isLoop`; нулевая площадь (out-and-back,
  пустая геометрия) → тайбрейкер totalMinutes; варианты с равным скором —
  побеждает большее покрытие.
- `isUnderfloor`: чистый предикат (недобор/граница/перебор).
- Регресс: все существующие тесты зелёные (499).

## Не делаем в этой волне

Уличный интерес-слой и `out geom` (docs/street-interest-wave.md), микростопы,
эксперт-режим, UI-перестройка кроме R5, maplibre, дневной счётчик ключей.

## Роадмап следующих волн (для контекста, не эта волна)

Волна «улицы» — Overpass `out geom`, StreetInterest, снап розы, микро-стопы.
Волна «human design» — maplibre-рендер, вход с главного экрана, шторка 45/85,
шаринг `?w=`, человеческие причины.
