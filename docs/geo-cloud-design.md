# Дизайн: CloudProvider — облачный тир geo-слоя

> Реализация тира 1 из ADR-001. Контракт: `next-app/src/lib/geo/types.ts` (заморожен).
> Зона файлов: `next-app/src/lib/geo/**` + `next-app/.env.example`. UI и server actions не затрагиваются.

## Цель

`CloudProvider` — реализация `GeoProvider` на публичных сервисах. Работает в любом
городе с первого дня, без собственного железа. Архитектура допускает второй
адаптер (`PackProvider`) без изменений контракта: порт один, композиция — в
конструкторе провайдера.

## Структура модулей

```
src/lib/geo/
  types.ts                     # ЗАМОРОЖЕННЫЙ контракт (только чтение)
  cache.ts                     # TtlLruCache + округление координат для ключей
  http.ts                      # fetchJson: таймаут, строгий парс, маппинг статусов в GeoError
  cloud/
    config.ts                  # CloudProviderConfig: ключи, endpoints, таймауты, зеркала
    validate.ts                # assertValidPoint/Waypoints/Alternatives, порядок [lat,lng]→[lng,lat]
    ors.ts                     # OrsRoutingAdapter: route + matrix с чанкингом
    photon.ts                  # PhotonAdapter: suggest + reverse (bias по точке)
    nominatim.ts               # NominatimAdapter + RateLimiter (1 rps), fallback для геокодинга
    overpass-places.ts         # OverpassPlacesAdapter: searchPlaces (зеркала, эскалация радиуса, коридор)
    cloud-provider.ts          # CloudProvider — композиция, кэши, валидация входов
  __tests__/                   # юнит-тесты на фейковых апстримах (vitest, node env)
    cloud.integration.test.ts  # живые тесты, CI исключает (--exclude "**/*.integration.test.*")
```

Каждый апстрим — отдельный класс-адаптер с инъекцией `fetchImpl`. `CloudProvider`
их только связывает: валидация → кэш → адаптер. Движок прогулки видит один
`GeoProvider` и не знает про HTTP.

## Политика таймаутов и ретраев

ADR-001: таймауты явные, ретраев на POST нет. Конкретика:

| Апстрим | Запрос | Таймаут | Ретраи |
|---|---|---|---|
| ORS directions | POST | 12 с | нет — повтор удваивает расход квоты бесплатного тира |
| ORS matrix | POST | 15 с | нет; матрица разбита на чанки ≤40 источников, чанк — минимальная единица повтора кэша, не сети |
| Overpass | POST | 12 с | нет; вместо ретрая — следующее зеркало |
| Photon | GET | 6 с | нет; вместо ретрая — fallback на Nominatim |
| Nominatim | GET | 6 с | нет; вышестоящий слой решает, что честно отдать |

Отклонение от формулировки ADR «connect ~1s»: у `fetch` нет переносимого
раздельного connect/read таймаута, поэтому у каждого запроса один явный бюджет.
Он щедрее 1 с на connect, но детерминирован и не зависит от DNS-хвостов.

Маппинг ошибок HTTP (централизован в `http.ts`, статусы живут в `cause.status`):

| Статус | Код GeoError |
|---|---|
| 404, 422 | `NOT_FOUND` |
| 429, 5xx | `UPSTREAM_UNAVAILABLE` |
| 400, 401, 403, прочие 4xx | `UPSTREAM_INVALID` |
| бюджет вышел | `UPSTREAM_TIMEOUT` |
| сеть упала (TypeError) | `UPSTREAM_UNAVAILABLE` |
| 200, но тело не JSON / схема не сошлась | `UPSTREAM_INVALID` |

Слой ORS донастраивает под семантику роутинга (см. «Деградация»).

## Лимиты бесплатных тиров и честная деградация

Точные квоты провайдеры меняют; актуальные цифры сверяются на их сайтах
(openrouteservice.org/dev, operations.osmfoundation.org — Nominatim). Дизайн
держится не на цифрах, а на механизмах:

- **ORS** — квоты на день/минуту. Ответ 429 или отклонённый ключ (401/403)
  для `route()`/`matrix()` маппится в `GeoError('NO_ROUTE')` с внятным message
  (нет ключа / квота исчерпана / ключ отклонён) — движок честно скажет
  «маршрут не построился», а не «сервис упал». Отсутствие переменной
  `OPENROUTESERVICE_API_KEY` — тоже `NO_ROUTE`, сеть даже не дёргается.
  5xx и таймаут остаются `UPSTREAM_UNAVAILABLE`/`UPSTREAM_TIMEOUT` — это
 (transient) лежание провайдера, не отсутствие маршрута.
- **Чанкинг матрицы**: ≤40 источников на запрос, все цели в каждом запросе.
  Локации запроса = [чанк источников …, все цели], `sources` — относительные
  индексы `[0..k-1]`, `targets` — `[k..k+T-1]`. Ответная строка `r` клеится в
  глобальный источник `chunkStart + r`, столбец `c` — в глобальную цель `c`.
  Именно здесь уже ловили баг с индексами; тест фиксирует и размер чанков, и
  склейку, и то, что цели в каждом чанке идут с относительными индексами.
- **Nominatim** — публичная политика 1 запрос/сек, User-Agent обязателен.
  `RateLimiter` резервирует слоты по времени старта запроса: параллельные
  вызовы выстраиваются, пауза между стартами ≥ 1000 мс. Вызывается только
  когда Photon промолчал или ошибся.
- **Photon** — публичный, без ключа; нагрузку снимают кэш и то, что он первый
  в лестнице геокодинга.
- **Overpass** — зеркала (список из `overpassClient.ts`), POST-запрос с
  `[out:json][timeout:12]`. Победившее зеркало запоминается (sticky); при его
  падении — один круг `Promise.any` по остальным. Не шлём два метода на
  зеркало, как делает старый клиент: POST поддерживают все.
- **Деградация по контракту**: нет данных → `null`/`[]`, сервис лежит →
  `GeoError(UPSTREAM_*)`. В частности:
  - `route()` — всегда сегмент или GeoError, выдумок нет;
  - `matrix()` — недостижимая ячейка = `null`/`null` (ORS отдаёт null в матрице);
  - `searchPlaces()` — нашлись частично до падения зеркала → частичный ответ;
    не нашлось ничего и зеркала упали → `UPSTREAM_UNAVAILABLE`;
  - `reverseGeocode()` — оба геокодера ответили «пусто» (или первый пусто, второй упал) → `null`;
    оба упали с ошибками → наверх уходит `GeoError` (лежка ≠ «здесь ничего нет»);
  - `suggest()` — аналогично: оба пусто → `[]`, оба упали → `GeoError`;
  - `isFastArea()` — всегда `false` (пакетный тир появится позже).

## Кэш

Единый `TtlLruCache` (TTL + LRU-вытеснение, recency обновляется при чтении).
Ключи координат — округление до 5 знаков (~1.1 м); в апстрим уходят **те же
округлённые координаты**, чтобы кэш и сеть согласованы.

| Кэш | Ключ | TTL | Объём |
|---|---|---|---|
| маршрут | округлённые waypoints | 10 мин | 200 |
| чанк матрицы | округлённые locations чанка | 10 мин | 200 |
| места | точка + категория + радиус + toward + limit | 10 мин | 200 |
| обратный геокод | точка | 60 мин (пустой ответ — 5 мин) | 300 |
| подсказки | нормализованный запрос + near | 10 мин | 300 |

Ошибки не кэшируются: севшая квота не должна «отравлять» маршрут на 10 минут.
Пустые ответы кэшируются (это настоящий ответ апстрима, а не ошибка).

## Валидация входов

`assertValidPoint`: пара `[lat, lng]`, оба — конечные числа, lat ∈ [−90, 90],
lng ∈ [−180, 180]; иначе `GeoError('INVALID_INPUT')` — **до** любого обращения
к сети (тесты это фиксируют: fetch-шпион не вызван). `route` требует ≥2
waypoints, `matrix` на пустых списках возвращает `[]` без запроса (пар не
существует — это не ошибка входа). Неизвестная категория в `searchPlaces` —
`INVALID_INPUT`.

## DI и тестируемость без сети

- Конструктор `CloudProvider(config?)`: `fetchImpl` (по умолчанию `global fetch`),
  ключи и endpoints, таймауты, список зеркал, `nominatimMinIntervalMs`.
  Ключ ORS: `config.orsApiKey ?? process.env.OPENROUTESERVICE_API_KEY`;
  пустая строка в конфиге = «ключа нет» — детерминированные тесты не зависят
  от окружения.
- Все юнит-тесты — на фейковых `fetchImpl` с таблицей маршрутов «URL → ответ»
  и записью вызовов; ноль живой сети. Лимитер и кэш принимают инъекции
  `sleep`/`now`, так что rate-limit и TTL проверяются без реального ожидания.
- Живые проверки — `cloud.integration.test.ts`, гейтятся по наличию ключа в env;
  CI гоняет vitest с `--exclude "**/*.integration.test.*"` (как в ci.yml).

## Осознанные упрощения

- `RouteRequest.alternatives` контракт допускает (0–2), но `route()` возвращает
  один сегмент — CloudProvider отдаёт основной маршрут; альтернативы не
  запрашиваются у ORS (лишний расход квоты без потребителя на этом слое).
- Кэш матрицы — на чанк-запрос, не на ячейку: перекрывающиеся вызовы с другим
  разбиением не попадут в кэш. Ячеечный кэш — оптимизация для PackProvider.
- Локаль запроса в геокодеры не передаётся (серверный слой, i18n не входит в
  зону); Photon/Nominatim отдают свои дефолты.
- Open-Meteo (погода в ADR) — не часть `GeoProvider`, сюда не входит.
